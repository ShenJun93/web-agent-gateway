# V0.1 MCP Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover the original `verify.run` result after transport/session loss while the gateway process remains alive.

**Architecture:** Reuse the pinned MCP SDK experimental Tasks API. A gateway-lifetime `InMemoryTaskStore` is shared by per-request stateless MCP servers. `verify.run` becomes `taskSupport: optional`, preserving synchronous compatibility while task-aware clients can reconnect and call `tasks/get` / `tasks/result`.

**Tech Stack:** TypeScript, Node 24, `@modelcontextprotocol/sdk@1.29.0`, Zod 4.5.4, pinned DevSpace 1.0.8.

**Spec:** `docs/adr/0006-use-mcp-tasks-for-durable-verify-results.md`

## Global Constraints
- Keep the public tool names at exactly five; do not add `job.*` tools.
- No mutation, raw shell, Git mutation, database task store, or gateway-restart durability.
- Task TTL must be bounded; default V0.1 result retention is 5 minutes.
- Do not advertise task list/cancel capabilities in V0.1; only tool-call task creation is advertised.
- Task-aware reconnect recovery must use the same bearer-authenticated HTTP boundary and opaque workspace IDs.
- Existing non-task `verify.run` behavior must remain compatible.
