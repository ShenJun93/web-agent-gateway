# V0.1 MCP Tasks Gate

Date: 2026-09-10
Decision authority: ADR-0006
Scope: recover the original `verify.run` result after transport/session loss while the same gateway process remains alive.

## Decision

**V0.1 MCP task result recovery: PASS.**

The prior V0 blocker is resolved for transport/session loss in the same gateway runtime. A task-aware client can receive a task ID, lose its public transport, reconnect through a replacement transport, call `tasks/get`, and recover the original structured `verify.run` result through `tasks/result`.

This does **not** authorize mutation, raw shell, Git mutation, a database task store, or gateway-restart durability.

## Evidence

Implementation checkpoints:
- `9e6474b9834722f69c40f09cc63e91f87f70c8c7` — task-capable `verify.run` using official MCP Tasks.
- `75bd8d0878b0a545dc7533d973dd5b5b8185878c` — two-client reconnect result recovery integration proof.

Public transport acceptance uses `cloudflared 2026.8.3`, SHA-256 `83e726ed18ea78c5ad5213c4c3a3a27051393950d2bc8ed4de69bec12d14eaae`.
Transport-only disposable fixture HEAD: `4a3c1089999b9af04f6df91065b4ca1710eb4f23`.

Attempt 1 is retained as a harness-infrastructure failure: the public-boundary readiness probe had no per-attempt fetch timeout and remained stuck for more than four minutes. It produced no gateway-task verdict. The harness was corrected with a 3000 ms per-request abort timeout.

Attempt 2 passed:
- task ID obtained before cutting the first Quick Tunnel;
- local verification completed successfully in about 2171 ms;
- replacement Quick Tunnel connected to the same gateway runtime;
- `tasks/get` returned `completed`;
- `tasks/result` recovered `profile=transport`, `exitCode=0`, and output `TRANSPORT_JOB_COMPLETED`;
- fixture returned to exact HEAD;
- zero test DevSpace leaks and zero cloudflared leaks.

Raw receipt: `docs/benchmarks/transport-interruption-tasks.json`.

## Remaining blockers and exclusions

- Stable named public endpoint: **BLOCKED_NOT_CONFIGURED**. Quick Tunnel setup took about 29.3 s and 25.1 s in the passing attempt and remains provisional transport only.
- ChatGPT Plus private full-write MCP deployment: **BLOCKED_PRODUCT_ACCESS** under the previously recorded provider-access gate.
- Gateway process restart durability: **OUT_OF_SCOPE**. `InMemoryTaskStore` is sufficient for the transport-loss failure mode tested here but does not persist across gateway restart.
- Mutation/raw shell/Git mutation: **NOT AUTHORIZED**.
