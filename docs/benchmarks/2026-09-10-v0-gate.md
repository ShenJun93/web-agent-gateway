# V0 Gate Decision

Date: 2026-09-10
Status: LOCAL ARCHITECTURE GO / OVERALL V0 BLOCKED

## Decision
The provider-neutral read/verify architecture passes its performance and safety value gate. The V0 as a deployable/reconnect-safe product remains BLOCKED, not NO-GO, because lost-request result recovery is not implemented, no stable named public tunnel is configured, and ChatGPT Plus private full-write MCP remains unavailable.

No mutation tool is authorized by this gate.

## Comparable scope
Per ADR-0005, the comparison is the read/verify subset only. It contains repository snapshot, five reads, one verification run, and final snapshot. It is not mutation-equivalent to the original 12-call Desktop Commander coding scenario.

Exact fixture HEAD: `57bcd8421936f3e44dba4eda80bbb98f583f8432`.
## Performance evidence
Desktop Commander subset (5 runs): median 18.020 s, sample p95 24.184 s.

Authenticated loopback MCP -> Gateway -> DevSpace:
- cold: 2.528 s
- 5 warm runs median: 1.185 s
- warm sample p95: 1.191 s
- warm first-useful-action median: 215 ms
- speedup vs DC median: 15.202x

Authenticated Cloudflare Quick Tunnel (provisional):
- cold: 3.901 s
- 5 warm runs median: 2.377 s
- warm sample p95: 2.766 s
- warm first-useful-action median: 474 ms
- speedup vs DC median: 7.582x
- tunnel setup/DNS readiness excluded from measured scenario: 11.080 s observed


## Reliability and transport-loss evidence
- All measured MCP tool responses carried x-request-id; no silent drop was observed during benchmark runs.
- Quick Tunnel produced one cold optional GET/SSE 405; the MCP client continued successfully and all tool POSTs completed.
- Killing the public tunnel during `verify.run` did not kill local execution: gateway telemetry recorded verify success in 2.163 s and a post-reconnect `file.read` recovered the completion marker.
- The original in-flight MCP call was rejected after transport loss, and its stdout/result could not be recovered. Therefore process durability is PASS but lost-request result durability is FAIL/NOT IMPLEMENTED.
- No stable named Cloudflare Tunnel is configured on this machine. Quick Tunnel evidence is provisional only.

## Tool-turn and completion accounting
The ADR-0005 comparable read/verify subset uses 8 calls in Desktop Commander and 8 semantic MCP tool calls in each warm gateway run, so remote tool-turn reduction for this subset is **0**. The gain measured here comes from much lower per-call transport/orchestration overhead, not fewer calls.

Task completion rate for the 5 measured warm gateway runs was 5/5 on loopback and 5/5 on Quick Tunnel. The separate interruption test completed local work but the initiating request did not recover its result, so reconnect-safe task completion is not yet satisfied.

## Gate outcome
- Performance threshold: PASS (15.202x loopback warm median; 7.582x provisional Quick Tunnel warm median vs DC subset).
- Path/environment security: PASS for the tested V0 surface.
- Authenticated public Quick Tunnel: PASS PROVISIONAL.
- Stable public endpoint: BLOCKED / NOT CONFIGURED.
- Process survival across transport loss: PASS.
- Lost-request result recovery: FAIL / NOT IMPLEMENTED.
- ChatGPT Plus private full-write MCP deployment: BLOCKED by current product access.

**Decision:** retain LOCAL ARCHITECTURE GO, keep OVERALL V0 BLOCKED, and authorize a separate V0.1 decision to investigate official MCP Tasks for durable `verify.run` result recovery. Mutation, arbitrary shell, Git mutation, persistent custom job APIs, and plugin submission remain unauthorized by this gate.
